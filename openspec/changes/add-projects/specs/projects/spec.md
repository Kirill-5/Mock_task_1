# Spec Delta

## Purpose

Управление проектами через REST API: создание, получение и удаление проекта с соблюдением правил валидации, уникальности имени и ограничений на удаление проекта с задачами.

## ADDED Requirements

### Requirement: Создание проекта
Система SHALL создавать проект по `POST /projects` с телом `{name, description?}` и возвращать 201 с телом `{id, name, description, created_at}`. Пробелы по краям `name` и `description` MUST обрезаться; пустое или состоящее из пробелов `description` MUST сохраняться как `null`.

#### Scenario: Успешное создание проекта
- **WHEN** клиент отправляет `POST /projects` с `{"name": "Alpha", "description": "Первый проект"}`
- **THEN** система отвечает 201, в теле есть сгенерированный `id`, `name` = `"Alpha"`, `description` = `"Первый проект"` и `created_at`

#### Scenario: Создание без описания
- **WHEN** клиент отправляет `POST /projects` с `{"name": "Alpha"}`
- **THEN** система отвечает 201 и `description` = `null`

#### Scenario: Обрезка пробелов
- **WHEN** клиент отправляет `POST /projects` с `{"name": "  Alpha  ", "description": "   "}`
- **THEN** система отвечает 201, `name` = `"Alpha"` и `description` = `null`

### Requirement: Валидация имени проекта
Система MUST отклонять создание проекта с ответом 422, если `name` после обрезки пробелов короче 3 или длиннее 100 символов, а также если `name` отсутствует или не является строкой.

#### Scenario: Слишком короткое имя
- **WHEN** клиент отправляет `POST /projects` с `{"name": "ab"}`
- **THEN** система отвечает 422 и проект не создаётся

#### Scenario: Имя короче 3 символов после обрезки пробелов
- **WHEN** клиент отправляет `POST /projects` с `{"name": "  ab  "}`
- **THEN** система отвечает 422

#### Scenario: Слишком длинное имя
- **WHEN** клиент отправляет `POST /projects` с `name` длиной 101 символ
- **THEN** система отвечает 422

#### Scenario: Граничные длины имени
- **WHEN** клиент создаёт проекты с `name` длиной 3 и 100 символов
- **THEN** система отвечает 201 на оба запроса

#### Scenario: Имя не передано
- **WHEN** клиент отправляет `POST /projects` с `{}`
- **THEN** система отвечает 422

### Requirement: Валидация описания проекта
Система MUST отклонять создание проекта с ответом 422, если `description` после обрезки пробелов длиннее 1000 символов.

#### Scenario: Слишком длинное описание
- **WHEN** клиент отправляет `POST /projects` с `description` длиной 1001 символ
- **THEN** система отвечает 422 и проект не создаётся

#### Scenario: Описание максимальной длины
- **WHEN** клиент отправляет `POST /projects` с `description` длиной 1000 символов
- **THEN** система отвечает 201

### Requirement: Уникальность имени проекта
Имя проекта MUST быть уникальным без учёта регистра (сравнение после обрезки пробелов). Попытка создать проект с занятым именем MUST завершаться ответом 409, существующий проект при этом не меняется.

#### Scenario: Повтор имени в другом регистре
- **WHEN** проект `"Alpha"` существует и клиент отправляет `POST /projects` с `{"name": "ALPHA"}`
- **THEN** система отвечает 409

#### Scenario: Повтор имени с пробелами
- **WHEN** проект `"Alpha"` существует и клиент отправляет `POST /projects` с `{"name": "  alpha "}`
- **THEN** система отвечает 409

#### Scenario: Уникальность гарантируется на уровне хранилища
- **WHEN** в хранилище напрямую, минуя проверку в use case, записываются два проекта с именами, отличающимися только регистром
- **THEN** вторая запись отклоняется хранилищем

### Requirement: Получение проекта
Система SHALL возвращать проект по `GET /projects/{id}` с ответом 200 и телом `{id, name, description, created_at}`. Для несуществующего `id` MUST возвращаться 404, для `id`, не являющегося UUID, — 422.

#### Scenario: Получение существующего проекта
- **WHEN** проект создан и клиент отправляет `GET /projects/{id}`
- **THEN** система отвечает 200 и тело совпадает с ответом на создание

#### Scenario: Проект не найден
- **WHEN** клиент отправляет `GET /projects/{id}` со случайным UUID, которого нет в системе
- **THEN** система отвечает 404

#### Scenario: Некорректный идентификатор
- **WHEN** клиент отправляет `GET /projects/not-a-uuid`
- **THEN** система отвечает 422

### Requirement: Удаление проекта
Система SHALL удалять проект по `DELETE /projects/{id}` с ответом 204 без тела. Для несуществующего `id` MUST возвращаться 404, для `id`, не являющегося UUID, — 422.

#### Scenario: Успешное удаление
- **WHEN** проект без задач существует и клиент отправляет `DELETE /projects/{id}`
- **THEN** система отвечает 204, а последующий `GET /projects/{id}` возвращает 404

#### Scenario: Удаление несуществующего проекта
- **WHEN** клиент отправляет `DELETE /projects/{id}` со случайным UUID, которого нет в системе
- **THEN** система отвечает 404

#### Scenario: Удаление с некорректным идентификатором
- **WHEN** клиент отправляет `DELETE /projects/not-a-uuid`
- **THEN** система отвечает 422

#### Scenario: Имя освобождается после удаления
- **WHEN** проект `"Alpha"` удалён и клиент отправляет `POST /projects` с `{"name": "alpha"}`
- **THEN** система отвечает 201

### Requirement: Запрет удаления проекта с задачами в работе
Система MUST отклонять удаление проекта с ответом 409, если в нём есть хотя бы одна задача в статусе `in_progress`. Проект и его задачи при этом MUST остаться без изменений.

#### Scenario: Проект с задачей в работе
- **WHEN** в проекте есть задача в статусе `in_progress` и клиент отправляет `DELETE /projects/{id}`
- **THEN** система отвечает 409, а `GET /projects/{id}` по-прежнему возвращает 200 и задачи проекта сохранены

### Requirement: Каскадное удаление задач проекта
При удалении проекта система MUST удалять все его задачи. Задачи других проектов MUST оставаться без изменений.

#### Scenario: Задачи в todo и done удаляются вместе с проектом
- **WHEN** в проекте есть задачи только в статусах `todo` и `done` и клиент отправляет `DELETE /projects/{id}`
- **THEN** система отвечает 204 и задач этого проекта в хранилище не остаётся

#### Scenario: Задачи других проектов не затрагиваются
- **WHEN** удаляется проект A, а у проекта B есть задачи
- **THEN** задачи проекта B остаются в хранилище
